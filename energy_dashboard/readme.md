Energy Dashboard (FastAPI + Streamlit)

Простой веб‑сервис для просмотра и редактирования данных по энергопотреблению и ценам. Backend реализован на FastAPI и работает поверх SQLite, frontend — на Streamlit.

Структура проекта

- backend/main.py — API для доступа к данным:
    - хранение записей в таблице energy_records;
    - эндпоинты для чтения, добавления и получения записи по ID.​
- frontend/dashboard.py — интерактивный дашборд:
    - таблица с данными;
    - графики потребления и цен;
    - панель добавления и удаления записей.
- energy.db — база данных SQLite с примером датасета.

Запуск

1.  Установить зависимости (пример):

bash

**pip install fastapi uvicorn sqlalchemy pydantic streamlit requests pandas**

1.  Запустить backend:

bash

**cd energy_dashboard**

**uvicorn backend.main:app --reload**

API будет доступен по адресу http://127.0.0.1:8000. Документация Swagger: http://127.0.0.1:8000/docs.​

1.  Запустить frontend:

bash

**cd energy_dashboard**

**streamlit run frontend/dashboard.py**

Дашборд откроется в браузере (обычно http://localhost:8501).​

Функциональность дашборда

- Отображение данных:
    - таблица с временным рядом потребления и цен;
    - два графика: потребление (EUR и SIB) и цена (EUR и SIB).
- Оконный просмотр:
    - данные загружаются целиком из API, но на графиках и в таблице показывается только окно по времени;
    - размер окна (количество точек) и его сдвиг по всей истории задаются слайдерами в боковой панели;
    - по умолчанию отображается окно по последним значениям временного ряда.
- Редактирование данных:
    - добавление новой записи через форму (дата, время, потребление и цены);
    - удаление записи по ID.​

После добавления или удаления данных кэш загрузки данных сбрасывается, и дашборд автоматически подхватывает актуальное состояние базы.

Ограничения и объём данных

Приложение ориентировано на **не большой объём данных**, сопоставимый с предоставленным примером (несколько десятков тысяч строк).

- Все данные загружаются из backend в память Streamlit одним запросом и далее фильтруются на стороне фронтенда.
- Чтобы не подтормаживало графики строятся только по скользящему окну, размер которого устанавливает пользователь. Это окно пользователь может сдвигать.
- Сервис **не предназначен** для работы с очень большими таблицами (сотни тысяч и миллионы строк); для таких случаев потребуется доработка API (фильтрация и пагинация на стороне backend) и более агрессивное упрощение временных рядов.
